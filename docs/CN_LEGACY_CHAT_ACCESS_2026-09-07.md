# 国内旧聊天入口权限修复

## 问题与修复

应用自动发现并挂载旧 `/api/v1/chat`，该接口过去接受客户端 user_id，按字符串前缀推定付费，使用独立模型与模板回退路径，绕过正式聊天服务。会话列表、查询、删除缺少登录依赖，历史接口还缺少所有者检查。

旧入口现保留原 success/data 响应封装和 JSON/查询参数消息输入，但身份只取登录令牌；生成结果复用正式国内聊天服务，会员等级从服务端权益读取。读取、续写、删除旧会话均校验身份与归属。未配置网关返回 503；危机援助沿用正式安全处理，不依赖模型可用性。输入长度与正式入口一致。

测试通过真实应用路由、两位登录用户、伪造 user_id、跨用户查询/续写/删除来验证，供应商调用被拦截，不涉及真实模型或付款。旧 E2E 聊天用例改为正式应用与真实登录，避免仅在简化测试应用中匿名调用造成虚假通过。

## 尚未闭环

- 旧会话索引仍在进程内，正式消息已持久化，但会话关联、重启恢复及多副本一致性尚未完成。本轮不宣称完整会话持久化。
- 共享额度尚未闭环：旧配置 10/100 与权益注册表 20/200 不同；正式聊天未统一接入原子额度账本。此次仅移除国内旧入口的重复扣减及以用户 ID 判断会员的错误路径。
- 旧国际 `/ai/chat`、其他自动挂载路由仍需逐条审查；不能将本轮国内入口修复等同全 API 权限完成。
- 本轮未变更 UI，未作生产发布、真实付款或全专业准确性验收。

## 验证结果

全后端首轮回归为 3435 通过、7 跳过、3 失败；失败均为旧性能测试仍替换已移除的旧模型函数。现已将这些测试改用正式应用、真实登录和网关拦截，超长输入按明确的 4000 字符上限验证 422。最终相关聊天、旅程、性能与新权限回归共 57 项全部通过；未把这次局部重跑称为最终全量通过。Ruff F 检查修改的路由及新增测试通过。

旧会话现在记录本次正式调用持久化的消息 ID；授权删除时同步删除这些消息，测试直接查询数据库核验。重启后会话索引恢复仍待实现。
