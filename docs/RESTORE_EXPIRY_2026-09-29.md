# 恢复购买期限与收据选择修复（2026-09-29）

## 实际缺陷

旧恢复接口会在平台没有返回到期时间时从当前日期补出一年权益；无凭证时可能根据进程内购买历史再次开通。Android 验证返回 expiry_time_ms，但恢复接口只读 Apple 的 expires_at_ms。Apple 验证适配器优先使用客户端提供的交易编号，且直接取收据数组第一项，没有正确筛选交易和退款状态。

## 修改

恢复必须有有效的平台验证结果、准确登记的商品、平台交易编号及有效的未来到期时间。删除按本地历史补权益和默认一年分支，未知商品不再通过字符串包含关系匹配高级套餐。Android 使用自己的到期与自动续费字段。重复恢复相同交易与相同期限不延长权益；验证期限更新时采用新期限。

Apple 适配器从平台返回记录中匹配交易，按期限选择最新项，拒绝已撤销或缺少必要字段的交易，返回真实交易编号。未用客户端编号替代平台编号。

支付流程中另有 4 项旧测试依赖无凭证历史恢复，已改为验证平台到期时间、过期拒绝和重复恢复不延期。

原有恢复测试逐项使用明确登录用户；成功收据测试提供平台到期时间，而不是要求缺失期限仍开通。原来可能因历史列表为空而虚假通过的收据摘要测试，新增非空断言。

## 验证

恢复、Apple 交易选择及访问控制专项 80 通过；连同支付全流程最终组合测试 145 通过。全部为本地数据库和模拟平台响应，不是真实 App Store / Google Play 交易验收。

官方依据：

- [Apple 订阅到期字段](https://developer.apple.com/documentation/appstorereceipts/expires_date_ms)：按平台期限与当前时间判断访问资格。
- [Apple 退款与撤销字段](https://developer.apple.com/documentation/appstorereceipts/cancellation_date_ms)：撤销记录仍可能保留在收据中，需要明确检查。

## 尚未完成的代码与外部事项

此旧恢复路径仍使用进程内 subscriptions / purchase_history，与持久化会员权益表未统一；跨账号交易归属、跨进程幂等、退款后的已有权益同步仍需补齐。旧 verifyReceipt 接口还应迁移到 App Store Server API / 签名交易校验，并完成生产和沙箱环境策略检查。因此不能据此宣布应用内购买恢复已达到生产要求。

国内支付宝/微信订单恢复不属于此 iOS / Android 收据接口，本轮没有把国内订单转到境外渠道。服务器、商户及应用商店真实验收尚未执行。

最终完整后端回归：3329 通过、412 失败、18 跳过。相比上一轮减少 10 项失败，新增 27 项测试通过；整体仍未全绿，仅推送修复分支。
