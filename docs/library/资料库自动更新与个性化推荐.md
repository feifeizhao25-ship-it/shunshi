# 官方资料库：自动更新 + 个性化推荐（顺时）

> 这一页说明资料库怎么“保持更新”、怎么“推给每个人”。资料本身（12 条）见 `待审核资料库说明.md`。
> 一句话：**机器负责发现变化、提醒人；人负责审核；用户只会看到审核过、且来源没有悄悄变化的内容。**

## 一、自动更新

### 谁在跑
挂在 SIL 已有的调度槽上，不另起调度器（`backend/app/self_improve/library_job.py`）：

| 任务 | 时间（北京时间） | 做什么 |
|---|---|---|
| `library-check` | 每天 02:00（`daily_scan` 槽） | 重新抓取每条资料登记的官方来源，和上次比对内容摘要，写状态文件 |
| `library-discover` | 每周日 03:00（`weekly_cycle` 槽） | 读权威来源的“列表页”，把新发布文件的标题和链接暂存为候选 |

- 默认关闭：只有设置 `LIBRARY_FRESHNESS_ENABLED=1` 才运行；和 `SIL_ENABLED` 互相独立（SIL 继续关着也可以单独开）。
- 复用 SIL 的白名单抓取（仅 https、仅白名单域名、不跨域跳转、限大小）、来源登记和 `worklist.jsonl`。
- 手动运行：`python -m app.self_improve.run library-check` / `library-discover`。
- 数据目录：`SHUNSHI_LIBRARY_DIR`（默认 `var/library`），里面有 `library_state.json`、每条的 `*.baseline.txt` / `*.latest.txt` 快照、`reference_entries.json`（审核后的条目）、`library_review_log.jsonl`（审核记录）。

### 检测什么
每条资料对照它登记的官方来源页：

| 结果（`check`） | 含义 | 用户看到什么 |
|---|---|---|
| `ok` | 内容摘要没变 | 正常显示，带“核对于 日期” |
| `minor_change` | 只有标点/个别字变化（<0.2%，数字和“废止”等标记没变） | 正常显示 |
| `changed` | 内容变了 | 条目留在列表里，但挂黄色提示“官方原文近期有变动，本条内容还没有对照最新版本”；**不再被推荐** |
| `repeal_signal` | 标题或开头出现“已废止/已失效/被替代…” | **从列表、推荐、首页卡片里整条消失**；直接打开只看到“已废止”提示 |
| `url_broken` / `unreachable` | 404/410 / 连不上 | 连续 3 次以上：提示“暂时无法核对来源”，不再推荐 |
| `refused` / `manual` | 来源不在白名单 / 只能人工核对（卫健委返回 412、人大网和 nbphsp 机器访问不了） | 不假装核对过；靠“核对周期”提醒人工复核 |

另有**核对周期**：条目超过 90 天没人核对（消费提醒 45 天）就显示“已超过核对周期”，同样不再推荐。

### 审核（人）
任何变化都只写状态，**不会自动改条目、不会自动上线**：`POLICY_REVIEWERS` 保持为空，SIL 保持关闭。审核人用命令行（必须写审核人姓名）：

```
python -m app.library.review_cli approve ss-lib-005 --reviewer 张三
python -m app.library.review_cli update  ss-lib-005 --reviewer 张三 --note "成年人每周中等强度活动时间的表述更新"
python -m app.library.review_cli confirm ss-lib-005 --reviewer 张三      # 看过了，内容没变化
python -m app.library.review_cli repeal  ss-lib-005 --reviewer 张三 --note "已被新版替代"
```

通过后条目带 `last_verified_at`、`reviewed_hash`（和审核时看到的来源页绑定）、`updated_on` 和 `change_note`；用户在资料库里会看到“核对于”“更新于”徽标和“更新说明”，30 天后徽标自动消失。

### 新文件怎么发现
`library-discover` 读 `data/sources.json` 里登记的列表页（卫健委、体育总局等官方域名），只把**标题含关键词、域名可信、之前没见过**的链接暂存为候选（首次运行只收 45 天内的）。候选永远不可见，带出处、抓取时间和“只读过标题，正文未读”的标记，并按证据账本的格式写出一行（B 级，待核）。要不要写成资料，仍然是人决定。

## 二、个性化推荐（只在应用内，不发通知/短信/邮件）

- 接口（登录用户）：`GET /api/v1/library/feed`（为你推荐）、`GET/PUT /api/v1/library/preferences`（总开关、关注/取消关注/不再推荐某主题）、`POST /api/v1/library/visit`、`POST /api/v1/library/opened/{id}`。`GET /api/v1/library/entries` 谁都能看，登录后多带“相对上次来访：新/已更新”。
- 只用用户自己提供的和应用里做过的：**目标**（来自 #29 的 `profile:onboarding`）、**自选体质倾向**（`profile:constitution`，理由里永远写“自评，不是诊断”）、年龄段、**关注的主题**、**读过哪些**，以及日历（**节气/季节**）。只读这些设置，不写；与 #29 的“个性化开关”联动，关了就都不推。
- 打分：关注主题 +5、目标匹配 +3、体质 +3、当前节气前后 3 天 +3 / 其余季节 +1、家人目标 +2、读过同类 +1（上限 2）；读过这一条 −6，近几天推荐过 −3/−2（所以每天会换）；有更新只对在意这个主题、或之前看过旧版的人加分并显示“更新”。
- 每一条都写**为什么推荐**；有**“新/已更新”**标记（相对上次来访）；可以**关注/不再推荐**主题；有**总开关**，关闭后不推荐也不记录读过什么。
- **未成年人**不推送饮食、体质、消费类主题。
- **地区**：现有 12 条资料没有地区差异，所以不拿地区当推荐理由（以后有地区资料再加）。
- 首页卡片：`library_for_you`，只在“有新增/更新”或匹配度很高时才出现一张，否则不打扰；接入见 #29 的个性化首页（另一个 PR，可选导入，没有这个模块时首页照常）。

## 三、测试
- 后端 `backend/tests/test_library_live.py`：5 个用户 × 7 天，周四来源变化（数字改了）、一条来源页出现“已废止”；断言每天 5 人的推荐互不相同、更新只出现在相关用户的推荐里、被替代/废止的条目任何人都看不到“现行”、周四来源变化的条目立刻停止被推荐、理由里没有诊断/疗效用语、未成年人不收到饮食类。
- App `test/library/library_live_test.dart`：推荐理由、新/已更新、横幅、更新说明、设置（关注/不再推荐/总开关）、保存失败恢复、总开关关闭、后端连不上时退回离线资料。
- 所有网络请求都用假的抓取函数；真实来源的抓取在盒子上做过两次冒烟（24 个地址，可抓取的内容稳定）。

## 四、上线前人要做的
1. 审核人逐条核对 12 条待审资料后再 `approve`（现在全部“待审核”，用户看不到）。
2. 生产环境显式设置 `LIBRARY_FRESHNESS_ENABLED=1`。
3. 卫健委、人大网、nbphsp 三个来源机器核对不了，需要人定期用浏览器复核（`manual` 状态会提醒）。
