# 国内 5×7 时钟回放

接口部分可重复运行。它不是墙上连续 7 天，也不是 Android、iOS 真机通过。

国内 Flutter Web 可以另外接这套测试时钟。构建必须显式打开测试开关，后端必须是 `SHUNSHI_ENV=test` 或 `testing`：

```bash
flutter build web --dart-define=API_BASE_URL=http://127.0.0.1:8091 --dart-define=APP_VARIANT=android-cn --dart-define=SHUNSHI_TEST_CLOCK=true
python backend/scripts/capture_domestic_web_clock.py --web http://127.0.0.1:8090 --api http://127.0.0.1:8091 --out /tmp/shunshi-web-clock
```

网页脚本走真实的引导、游客体验和资料向导，再把浏览器语言设为 `zh-CN`。画像里的目标仍由已有的 `POST /api/v1/seasons/onboarding/complete` 写入，因为资料向导不发送 `help_goal`。页面文字来自无障碍语义树。十二时辰按浏览器本地钟，节气条来自 `/api/v1/solar-terms/current`，这两处不读 `test_now`。这是 Web，不是原生。

命令（在 `backend/` 下，需要本机 Redis，测试会自己起一个只给额度用的实例）：

```bash
SHUNSHI_5X7_OUT=/tmp/shunshi_domestic_5x7.json python -m pytest tests/test_domestic_5x7_clock_replay.py -q --tb=short
```

不设 `SHUNSHI_5X7_OUT` 时测试仍执行，只是不写 JSON。

测试环境可以把 `X-Shunshi-Test-Now` 设成带时区的时间，首页和完成动作都用这一刻。`SHUNSHI_ENV` 不是 `test` / `testing` 时这个头被忽略。它不创建账号，也不代替登录。Flutter 只有在 `--dart-define=SHUNSHI_TEST_CLOCK=true` 时才从页面地址的 `test_now` 查询参数带上这个头；正式包没有这个开关。

## 时钟

- 五人七天：2026-11-02 起连续 7 个上海日期，每天都是 08:00。日期变化会带动「看过的卡片」轮换、工作日/周末和节气锚点。钟点不变，所以前后两天的差别不能算成早晚时间。
- 完成动作对照：2026-11-04 21:00 固定不变。动作记录的时间也被钉在这一刻，和首页使用的是同一个瞬间。

## 现有设计里，什么动作影响什么

首页计分没有因为这次验收改过。完成「sleep」时，只有类别同为 sleep、并且卡片自己带目标的建议会加上「你最近做过同类小行动」：同类加 1.5，刚做过再减 1，净增 0.5。其他类别的分数和 reason 不变。本周条和连续天数会记下这一天。没有做动作的对照账号必须与动作前完全一样。

付费档不改变这套首页排序。免费 20、内容订阅对应的 plus 100、会员对应的 pro 200，只出现在对话额度里，数字来自当前权益注册表，测试不修改它们。

## 资料库

HTTP 请求打到仍是待审核的生产资料。推荐列表为空，只证明关注、取消关注、不再推荐可以写入并删掉。测试不填写审核人，也不改打包的资料文件。

「不再推荐会把一条拿掉」用 `fixture-sleep` / `fixture-move` 合成条目，直接调用排序函数。这组结果不能当成 HTTP 真实资料库已经有可发布条目。
