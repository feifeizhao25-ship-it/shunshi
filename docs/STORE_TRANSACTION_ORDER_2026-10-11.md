# 国内 iOS 商店交易处理顺序修复（2026-10-11）

原购买事件处理器对 restored 调用异步恢复函数但未 await，platformVerified 又默认 true，导致服务端尚未验收据/恢复权益就可能执行 completePurchase。异步流的相邻批次也可能重叠处理；单笔 completePurchase 抛错会中断当前批次。

本批抽取串行 PurchaseUpdateProcessor 并接入真实 StoreService。purchased/restored 必须等待服务端验证成功才完成交易；返回 false 或抛异常时保留待处理状态，后续 SDK 事件可再次验证。pending 不完成。error/canceled 保持 SDK 终态清理行为并通知失败，不验证或授予会员。每笔交易独立捕获异常，后续交易和批次继续处理；不添加客户端假权益或假到期时间。

两处收据请求增加 30 秒接收超时，避免一般无响应请求无限等待后续交易。该超时不是后台可靠任务队列或生产恢复承诺。服务重启后仍依靠平台未完成交易重新投递，核心重复入账防护仍由服务端负责。

## 验证

Flutter 测试共 12 项通过：6 项交易顺序场景与 6 项此前会员页回归。新增覆盖恢复验证未完成不得确认、购买与恢复验证失败后重试、pending 与失败/取消终态处理、相邻批次串行、验收据及完成交易异常后继续、已无需完成的交易不得重复调用完成接口。修改的服务/处理器/测试静态分析无问题。

处理行为参照本机已安装 in_app_purchase 包 README 的 purchaseStream/completePurchase 示例与说明核对，保留失败终态清理，修复成功交易的验证等待。测试为真实 Dart/Flutter 处理器执行，服务端和商店调用使用受控函数，不是 Apple 沙盒或真金付款验收。原始日志在 evidence/2026-10-11-store-transaction-order/。

## 边界

本批范围为 ios-cn；未宣称其他端同名 StoreService 已同步整改。商店重复初始化、恢复无记录时的结果提示、应用关闭/重启后的真实平台投递、商户配置、真实购买及退款仍需单独验收。队列串行不等于交易去重；同一交易重复投递仍可能再次验证，依赖服务端幂等。没有修改后端，也未重跑后端全量；此前 387 项后端失败仍未清零。四产品总体未完成生产上线验收。
