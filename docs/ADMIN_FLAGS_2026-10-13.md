# 国内管理后台功能开关修复（2026-10-13）

## 已确认的问题
管理页请求 /api/v1/flags，但旧 feature_flags/router.py 未进入国内自动路由发现范围。页面读取预期 data，旧实现返回 flags；页面 PUT enabled，旧接口要求 PATCH value。读取失败或空列表会替换为八条硬编码的默认开关，误示家庭共享等功能已经启用。旧路由还允许 dev-admin-token。生产全局开关对象只从内存取值，没有保证其他进程读到已保存变化。

## 本批修改
- 新增 /api/v1/admin/flags 的 GET、PATCH 接口，使用现有管理员持久会话和统一管理员权限边界。
- 国内启动显式创建配置表，不自动灌入虚构功能或境外支付预设。
- 列表展示真实持久化数据，不返回白名单用户标识，只给数量。
- 本批只允许 boolean 类型且 key 匹配 prompt.<key>.gray 的配置更新；app/prompts/store.py 有此消费规则。其他未确认绑定和境外支付配置只读。匹配消费规则不代表该具体提示词有可用灰度版本，页面明确说明此限制。
- PATCH 仅接受 value 和 expected_updated_at，拒绝未知字段与字符串布尔值。同一事务内核对版本，冲突返回409；保留比例、说明、分类和白名单，不用默认值覆盖它们。
- 白名单可覆盖默认关闭，故存在白名单时拒绝“关闭”操作，防止误示已完全关闭。
- 全局生产 FlagStore 在读取时刷新数据库。单独创建的内存 FlagStore 仍用于已有算法单测；新测试以 read_through=True 检查多实例可见性。
- 无用户标识时不再绕过部分灰度比例。
- 旧未挂载路由也移除环境令牌及开发默认令牌回退。
- 中文页面区分加载、真实空数据、读取失败、修改未确认及成功，使用PATCH，限制未绑定开关操作并处理并发保存。
