# 应用内购恢复持久化与归属修复（2026-09-29）

## 变更

新增 store_purchase_owners 保存购买链的账号归属，store_purchases 保存经验证的交易结果。交易编号与购买链标识按渠道散列；不保存原始收据或 Google 购买令牌。Apple 使用平台返回的 original_transaction_id 关联续订链；Google 使用已提交验证的购买令牌散列。

交易归属和 Entitlement 权益表在一个数据库事务中更新。账号行写锁串行化同一用户的恢复请求；唯一键限制同一交易和购买链的账号归属。发生冲突或提交失败时回滚，不提前更新内存成功状态。

商品映射到权益注册表中的国内套餐，恢复后 /subscription/status、旧订阅查询及购买历史可读取持久化结果。恢复别名接口共用该事务。旧凭证不能缩短期限；已有其他渠道的未到期会员不被应用商店凭证覆盖。重复恢复不制造新的交易行，也不重置现有家庭成员缓存。

账号导出包含购买记录摘要。注销删除账号和当前权益，但保留购买归属与交易账本，响应明确报告保留数量，以防同一凭证注销后转到其他账号。保留期限和后续匿名化政策仍需结合实际业务制定，本实现不宣称已完成全部隐私合规审查。

## 部署

两个新表沿用 main.py 启动建表流程，建在配置的账号数据库中；部署账户需要建表及索引权限。没有把原内存数据伪装成已验证账本，旧记录需要再次平台验证。现有表未删除或改列。

## 验证

- 恢复购买、交易选择、访问控制、支付流程及账号删除组合：158 通过；补齐简化测试应用的数据库依赖并加入用户旅程、账单生命周期后，最终组合 177 通过。
- 新增 8 项覆盖重建应用后的权益与历史、跨账号购买链和交易冲突、旧凭证、国内权益冲突、注销保留归属、别名共享事务、注入提交失败后的完整回滚。
- 本机 PostgreSQL 17 临时库运行并发测试：同一交易跨账号争用只有一方成功；同账号并发恢复保留较长期限；重新打开数据库会话核对账本和权益。
- 平台响应为测试替身，没有真实扣款或连接生产应用商店。

## 剩余边界

尚未完成应用商店退款/撤销事件向既有权益的同步、App Store Server API 迁移、生产与沙箱环境验收、Google 更换购买令牌后的链关联、完整家庭席位持久化。部分旧功能还读取进程缓存，需要继续统一权益消费路径。并发验收只覆盖应用商店恢复请求间的竞争，尚未覆盖应用商店与国内支付回调同时更新的跨渠道竞争。本轮不代表四产品或应用内购整体达到上线要求。

证据：docs/evidence/2026-09-29-store-persistence/。postgres-check.py 仅用于已新建的本机临时测试库，不可直接用于生产库。

最终完整后端回归：3337 通过、412 失败、18 跳过。失败数量与上一轮相同，新增 8 项通过；保留失败明细，仍不合入主分支。
