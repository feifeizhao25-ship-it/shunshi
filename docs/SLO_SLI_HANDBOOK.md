## 五、监控告警规则

### 5.1 告警级别

| 级别 | 条件 | 通知方式 | 响应时间 |
|------|------|----------|----------|
| P0 Critical | 可用性 < 95% 或完全不可用 | 短信 + 电话 | 5 分钟 |
| P1 Warning | P99 > 目标值 2x 持续 5 分钟 | 短信 + 微信 | 15 分钟 |
| P2 Info | 错误率 > 1% 持续 15 分钟 | 微信 | 1 小时 |
| P3 Debug | 缓存命中率 < 50% | 日志 | 次日 |

### 5.2 关键监控指标

| 指标 | 数据源 | 告警阈值 |
|------|--------|----------|
| HTTP 错误率 | Prometheus `/metrics` | > 1% (5min) |
| AI 响应延迟 P99 | Prometheus histogram | > 10s (5min) |
| Redis 连接数 | Redis INFO | > 80% max |
| DB 连接池 | SQLAlchemy pool | > 80% capacity |
| 磁盘使用率 | Node exporter | > 85% |
| 内存使用率 | Node exporter | > 90% |
| LLM Token 消耗 | 自定义 Counter | 日预算 120% |

### 5.3 监控栈

```
Prometheus (9090) → 采集 /metrics
    ↓
Grafana (3000) → 可视化 Dashboard
    ↓
AlertManager → 告警路由（微信/短信/邮件）
```

配置文件：
- `backend/monitoring/prometheus.yml`
- `backend/monitoring/grafana/`
- `backend/docker-compose.monitoring.yml`

## 七、灾难恢复

### 7.1 备份策略

| 数据 | 频率 | 保留 | 位置 |
|------|------|------|------|
| PostgreSQL | 每日 03:00 | 7 天 | /var/backups/ |
| SQLite (开发) | 每日 03:00 | 7 天 | /var/backups/ |
| Redis | AOF + RDB | 自动 | /var/lib/redis/ |
| 配置文件 | Git 版本控制 | 永久 | GitHub |

### 7.2 恢复时间目标

| 场景 | RTO | RPO |
|------|-----|-----|
| 服务崩溃 | < 5 分钟 | 0 (自动重启) |
| 数据库故障 | < 30 分钟 | < 24 小时 |
| 整机故障 | < 2 小时 | < 24 小时 |
| 区域故障 | < 4 小时 | < 24 小时 |

### 7.3 恢复步骤

```bash
# 1. 数据库恢复
sudo -u postgres pg_restore /var/backups/shunshi_$(date +%Y%m%d).sql.gz

# 2. 服务重启
sudo systemctl restart shunshi-backend

# 3. 健康检查
curl http://localhost:4000/api/v1/health
curl http://localhost:4000/api/v1/health/detailed
```

## 八、API 版本策略

### 8.1 版本规则

- 当前版本: `/api/v1/`
- 版本变更遵循 SemVer: MAJOR.MINOR.PATCH
- MAJOR 变更（不兼容）→ 新增 `/api/v2/` 路径
- MINOR 变更（向后兼容）→ 同一版本下扩展
- PATCH 变更（Bug 修复）→ 无需版本变更

### 8.2 废弃流程

1. 新版本发布后，旧版本标记 `Deprecated` 响应头
2. 30 天过渡期：旧版本仍可用，响应头增加 `Sunset: <date>`
3. 过渡期结束后，旧版本返回 410 Gone + 升级提示
4. 客户端最低版本检查：`app.min_version` 配置项

### 8.3 强制升级

当发生不兼容变更时：
```json
{
  "code": 426,
  "message": "请升级到最新版本",
  "min_version": "1.1.0",
  "download_url": "https://..."
}
```
