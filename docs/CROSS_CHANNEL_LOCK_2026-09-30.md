# 支付权益跨渠道并发修复（2026-09-30）

国内支付回调原先先读取核心账号及权益，再写入权益；商店恢复购买则先锁定账号。国内账本 SQLite 的写锁不能约束独立核心数据库中的商店恢复请求，两者可能依据旧状态更新同一账号。

本次国内权益投影改为先对核心 User 执行不改变字段值的 UPDATE，取得与商店恢复、家庭席位相同的账号锁，然后读取并更新 Entitlement。账号不存在时仍返回 410；其他支付渠道冲突仍返回 409；已验证付款账本及恢复任务继续保留。没有改变金额、期限、验签、生产数据库配置检查。
