# 旧版账号入口真实性修复（2026-10-09）

## 问题与改动

旧版 DELETE /api/v1/users/{user_id} 尝试删除若干历史表，但读取了不存在的连接属性 row_count，且逐项吞掉异常。它没有删除核心账号，却可能返回“账户及所有关联数据已永久删除”。

现在旧版入口显式验证登录者与路径账号一致，并调用现有 /api/v1/auth/account 注销流程，覆盖核心账号、记录库和产品库个人数据，沿用令牌撤销与账务记录保留机制。兼容旧版 success、message、deleted_at、deleted_records、total_records_deleted 字段。删除数量按存储加前缀，避免同名表覆盖；部分清理未完成时 success=false，并列出未完成表。存储错误不会转换成成功响应。

旧版 GET /api/v1/users/{user_id}/export 原先只有少数历史表，现补入核心账号、设置、消息、健康记录、家庭席位与购买/账务摘要。保留旧版字段和 ISO 时间格式；不存在的历史表明确列入 unavailable_legacy_sections。导出范围明确标注为核心账号及所列历史记录，不宣称覆盖全部产品模块。历史表查询不再吞掉任意异常并伪装成空数据。

## 验证方法

原来的 24 个测试使用匿名调用并期望成功，部分只检查响应有某字段，不能证明账户真正删除。替换为 9 个真实登录场景：匿名/跨账号拒绝、删除确认、双账号导出隔离、导出后删除及令牌失效、部分清理与故障不得报告完全成功。断言实际核心账号、个人设置、家庭关系记录及删除计数。原有跨库注销、家庭会员、支付恢复测试同时回归。

专项组合 37 项通过。随后为了保留旧版导出时间格式增加 ISO 时间断言，最终版本由全库回归覆盖。原始日志见 evidence/2026-10-09-legacy-account/。

## 未完成范围

- 此改动没有实现所有产品模块的完整个人数据导出；已在返回值说明范围。
- 现有核心注销流程涉及多个数据库，仍不是单一原子事务，跨库部分失败的持久化补偿和后台重试尚需进一步完善。
- 账务保留周期、生产数据库删除效果和真实客户端操作仍需正式验收。
- 测试数量和失败数的变化包含测试重构，不应表述为修复了 24 个独立产品缺陷。

## 最终验证记录

- 第一轮全库：3360 通过、388 失败、17 跳过。与上一轮相比，24 个旧账号匿名成功测试已被重构替换，新增一个失败来自门禁测试仅创建旧记录库用户、未创建核心账号。
- 随后修正该门禁夹具，使其同时创建真实核心账号；本人导出的断言从“不是 401/403”加强为返回 200 且核心用户 ID 正确。
- 最终组合回归覆盖旧版账号、跨库注销、家庭席位、商店恢复、付款恢复任务以及完整产品门禁模块：72 项通过，4 条依赖/弃用警告。修正夹具后未再次重跑全库；上述 388 失败属于修正夹具前的全库结果，不能当作最终版本计数。
- 其他 387 个既有失败本轮未处理。失败数变化包含测试重构，不表示修复了等量产品问题。
- git diff --check、仓库完整性和部署配置检查通过。没有真实付款、正式服务器部署或客户端 UI 验收。
