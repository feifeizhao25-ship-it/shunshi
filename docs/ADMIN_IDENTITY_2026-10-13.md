# 国内管理后台登录安全修复（2026-10-13）

## 原问题
管理员令牌只存于单进程字典，不同工作进程或重启后无法识别登录。修改密码接口没有写入新密码却返回成功，且用户名未参与身份核验。Bearer 与 X-Admin-Token 在不同接口的处理不一致。

## 实现
- 产品数据库新增 admin_credentials、admin_sessions 表，适配 SQLite 和 PostgreSQL。启动建表与新增 Alembic 迁移均注册；requirements 增补 Alembic。
- 使用随机会话令牌，数据库仅存 HMAC-SHA256 摘要、到期时间和凭据版本，不存明文令牌。
- ADMIN_PASSWORD_HASH 为首次初始化凭据，首次成功登录升级为随机盐 scrypt 哈希。登录只接受配置的 ADMIN_USERNAME，默认 admin。
- 改密检查有效会话及旧密码，在同一事务中保存新密码、更新版本并撤销该账号全部会话。数据库失败回滚，不返回成功。新密码至少 12 字符。
- PostgreSQL 使用行锁，SQLite 使用 BEGIN IMMEDIATE，防止并发初始化和同时改密互相覆盖。旧会话在独立进程读取时同样失效。
- 统一 Bearer/X-Admin-Token；同时提供不同令牌时拒绝。登出持久撤销，过期令牌不能访问管理员接口。
- 新增后台“登录安全”页面、中文表单及确认输入，服务端确认后退出并引导重新登录。登录页支持填写管理员账号。
- 移除测试中对生产内存令牌表的注入，改为数据库会话测试夹具。家庭汇总测试改用每例独立记录数据库，避免全量测试残留干扰。

## 验证
相关 90 项测试通过，包含 SQLite、真实本地 PostgreSQL、独立 Python 进程验证、并发首次登录、并发改密、提交失败回滚、过期/登出/旧会话拒绝、迁移幂等和测试库降级再升级、生产配置启动。
管理端生产构建、修改组件 ESLint、原契约脚本通过。
真实 Chrome 对生产构建页面验证：两次密码不一致不发请求、失败不报告成功、重试成功清除凭证并跳转、手机宽度无页面溢出。家庭页原浏览器流程也通过。已查看 desktop.png、mobile-error.png、success-login.png。
浏览器使用受控 API，数据库测试为独立集成验证；未执行真实生产或远端支付验收。

本轮第一遍全量回归出现 390 失败，其中相较此前基线新增两项家庭测试数据污染和一项启动测试无效密码摘要，已修正夹具和配置，没有放宽授权或删除断言。最终全量结果为 **3492 passed / 387 failed / 17 skipped / 58 warnings**（201.29 秒），失败用例集合与此前 387 项基线一致，新增失败为 0。证据见 full-backend.txt 和 failure-comparison.json。现有 387 项仍未修复，不能声称后端全量通过。

测试期间临时环境 pyvenv.cfg、SQLAlchemy 部分文件和元数据缺失；恢复环境并重装相同 SQLAlchemy 版本后验证。初次迁移检查发现 Alembic 未列入依赖，已补齐；未绕过迁移测试。

## 配置与迁移注意
- 所有进程必须连接同一产品数据库、使用同一 ADMIN_JWT_SECRET（至少 32 字符）。
- 部署此更改时，之前只存于内存的会话不能迁移，管理员需重新登录。
- 环境变量中的初始摘要在管理员记录存在后不再覆盖密码；不能靠修改旧环境变量实现密码重置。
- 轮换会话密钥将使此前令牌无效；数据库密码仍保留。此批未实现遗失密码的运维恢复工具。
- 迁移不会改动已有业务表；生产备份与迁移执行仍未验收。不要用降级删除管理员凭据表作为常规回滚方案。
- 默认管理员账号仍是单账号方案，没有据此实现多管理员角色、双因素认证、共享限流或完整安全审计。这些不能标为通过。
- 老 feature_flags/router.py 仍有环境令牌兼容分支，本批未修改；其实际挂载与使用范围需继续核查。
- 管理端本地用 next start 检查生产构建；standalone 服务器启动和反向代理仍需独立验证。
- 四产品代码层尚未全部完成，暂不执行生产部署或真实付款。
