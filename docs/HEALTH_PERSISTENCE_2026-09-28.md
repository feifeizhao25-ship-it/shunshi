# 健康记录持久化与时间修复（2026-09-28）

## 用户可见变化

健康同步记录写入应用配置的账号数据库，不再使用进程字典。每条记录独立保存，避免多个请求改写同一个 JSON 数组而丢失数据。最近七天摘要按真实时间排序，排除未来与超过七天的记录；没有运行趋势分析时不显示“趋势分析中”。

ISO 时间统一转换为 UTC 后存储。历史国内客户端未附时区时，明确按北京时间解释；未来记录返回 422。健康记录纳入账号数据导出和注销删除，单独删除健康数据只影响当前用户。

## 数据结构与部署

新增 simple_models.HealthMeasurement / health_measurements 表及用户和记录时间组合索引。沿用应用 main.py lifespan 调用 app.db.init_db 的启动建表流程，对接 SHUNSHI_DATABASE_URL 指向的数据库；无需改动旧表字段。生产数据库账户需要相应建表权限，应在部署预演中核验。

旧实现没有落库，已经随进程退出丢失的历史记录无法补回。此轮不删除旧数据库、不伪造历史记录。回退代码不会自动删除新表，仍须保护其中个人数据。

## 验证范围

专项测试 84 通过：健康接口、准确性边界、访问控制、持久化和账号删除。新增五项用例验证应用重新创建后读取、时区排序、旧客户端时间解释与未来值拒绝、导出注销、用户删除隔离。

本机 PostgreSQL 17 临时库验证建表和索引、跨会话持久化、时间数值精度、删除回滚及提交；未使用生产数据库。证据见 docs/evidence/2026-09-28-health-persistence/。

完整后端回归：3255 通过、436 失败、18 跳过。失败数量与上一轮相同，新增五项通过；整体仍未全绿，不合并主分支。
