# 随访权限和到期查询修复（2026-09-27）

## 实际修复

- 随访详情原先只有任务 ID、没有身份参数，绕过统一 GET 门禁，可能匿名读取私密内容；现要求有效且仍存在的登录账号。
- 更新、取消接口不再仅按任务 ID 修改数据库，SQL 条件同时限制本人 user_id。其他账号访问返回 404，避免泄露任务是否存在。
- 全站 /followup/check 调度入口限制管理员，普通账号不得扫描并改变其他人的提醒状态。
- /check-due 注册在动态 /{followup_id} 之前，解决固定接口被当作任务 ID 的路由冲突。
- 个人到期查询直接在数据库内按本人及 pending/scheduled 状态过滤，不再扫描全站任务再在应用内筛选。
- 数据库读取错误返回 503，不暴露内部异常，也不伪装成成功的空列表。
- 原随访业务测试使用独立真实测试登录；保留业务行为断言，并替换原先只有 pass 或允许无创建记录通过的空验证。

## 验证

新增的首批五个安全回归在修复前全部失败（全站调度测试还在清理阶段报错），修复后五项通过。扩展到注销后旧令牌、读取失败以及既有业务/路由鉴权测试后，专项 76 项通过。另新增管理员调度授权测试，调度使用测试替身，无真实通知发送。

最终全量：3162 通过、506 失败、18 跳过（130.01 秒），比上一轮减少 26 个失败。新增的 8 项安全回归全部通过。完整证据见 docs/evidence/2026-09-27-followup。修复不会把所有未登录失败改成成功，也没有取消旧测试或跳过剩余失败。
