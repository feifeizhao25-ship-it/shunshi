# 国内聊天共享额度

三个国内入口 `/api/v1/chat`、`/api/v1/chat/send`、`/api/v1/ai/chat` 现在使用同一 Redis 原子预占机制，身份来自令牌、等级来自服务端权益，数量取权益注册表的 ai_daily_messages（免费 20、pro/family 200、enterprise -1）。键不包含原始用户 ID，按北京时间零点重置，Redis Cluster 两键使用同一槽位。

未配置 Redis 或服务故障返回中文 503，耗尽返回 429，均不调用模型。危机或直接安全阻断响应不消耗模型额度，不受 Redis 可用性影响。网关抛出异常时原子退款；重复退款不重复减计数。无独立数据库事务长时间等待模型的锁问题。

真实 Redis 测试验证免费/付费限额并发、重复退款、三个入口共享、伪造身份/会员字段、网关失败退款、Redis 不可用、北京时间日界线；相关聊天、旅程及性能测试共 64 项通过。CI 安装 redis-server，并由测试启动隔离的无持久化本地进程，不连接开发者实际 Redis。

Kubernetes 模板由 allkeys-lru 改为 noeviction，避免计数被淘汰后重新获得额度；持久化 AOF 使用 always，单实例采用 Recreate 避免滚动更新时同时写共享卷。这不是已部署证据；国内阿里云实际实例仍需确认持久化、淘汰策略、访问控制、资源与恢复流程。单实例重启期间服务会拒绝普通对话，不假报可用。

## 剩余问题

- 旧订阅展示中部分 unlimited_chat 文案与权益注册表冲突。本轮按注册表实现计数，不修改已售订单；必须在部署收费前完成订单承诺与注册表一致性核对，不能据此自动缩减历史权益。
- 进程在预占后异常退出、网关结果未知或 Redis 退款失败时，可能保守占用额度至当天结束；退款失败只记录异常类型，待补持久化对账/恢复机制。网关失败后的安全退还不代表外部模型服务退款。
- 此额度仅覆盖三个国内聊天入口，其他付费能力和国际旧入口不能据此标记完成。
- 模型响应成功后数据库提交失败仍需订单式执行记录来精确对账；本轮不宣称全链路 exactly-once。
- Redis 数据丢失恢复、真实生产并发性能和真实模型调用尚未验收。
